# Курс Deutsch A2 → B1

Локальное приложение (HTML + CSS + vanilla JS, без сборки). Открывается через `python3 -m http.server 8777` в корне проекта.

## Структура

- `index.html` — оболочка, подключает данные уроков, затем движок, затем приложение.
- `css/app.css` — все стили, светлая и тёмная тема через CSS-переменные.
- `js/engine.js` — рендер и проверка заданий. Глобал `window.Engine`.
- `js/app.js` — маршруты (hash), прогресс в localStorage, очередь повторения (Leitner, 3 бокса).
- `data/lessons.js` — `window.COURSE`: общий план всех 15 уроков (18–32), поле `status: ready | todo`.
- `data/lNN.js` — `window.LNN`: теория + дни + ссылки одного урока.

Новый урок = новый `data/lNN.js` + `<script>` в `index.html` + `status: "ready"` в манифесте.

## Источник материала

lehrerlenz.de, Lektionen 18–32. Оттуда берутся последовательность грамматики, темы и лексика.
Задания пишутся свои; ссылки на оригинальные интерактивные упражнения кладутся в `links` урока.
Урок 30 (Relativsätze) на сайте пустой — пишется полностью самостоятельно.

## Правила для теории (обязательно)

Теория — не пересказ таблицы. В каждом грамматическом блоке должно быть:

1. **Мнемо-хаки в блоке `.hack`** — приём, за который можно зацепиться и вспомнить правило под нагрузкой,
   а не выводить его заново. Нумеровать: «Хак № 1», «Хак № 2». Формулировать как действие,
   а не как описание («отрежь хвост у артикля», а не «окончание совпадает с артиклем»).
2. **Визуальная опора** — цветная сетка `.matrix`, схема-преобразование `.cut`, рифма/созвучие `.rhyme`
   или пошаговый алгоритм `.flow`. Хотя бы одна на блок.
3. **Подсветка того, что реально меняется.** Если из восьми клеток таблицы подвижна одна — сказать это прямо
   и выделить клетку классом `hl`. Ученик должен запоминать исключение, а не всю таблицу.
4. **Цвет рода последователен везде**: `der` — синий (`.m`), `die` — розовый (`.f`), `das` — зелёный (`.n`),
   Plural — серый (`.p`).
5. **Примеры с переводом**: блок `.ex`, немецкий жирным, русский в `.ru`.
6. **Ловушки называть явно** — «это главная ошибка урока», с примером правильного и неправильного.

Объяснения по-русски, все примеры и задания — по-немецки. Немецкий проверять: окончания, артикли, порядок слов.

## Правила для заданий

- Типы: `fill`, `choice`, `translate`, `pairs` (см. `js/engine.js`).
- **Время ученика — главный ресурс.** Задание проверяет знание, а не терпение:
  никакой механической работы, которая не тренирует правило.
- **`order` (собрать предложение из слов) не использовать.** Это перетаскивание
  плашек без проверки грамматики. Движок тип поддерживает только ради старых
  заданий, которые могут лежать в очереди ошибок.
- **Если проверяется окончание — вводится только окончание.** В `fill` это
  работает само: когда ответ = подсказка + хвост (`{klein}` → `kleiner`),
  основа печатается текстом и поле принимает только `er`. Нулевое окончание
  (сказуемое: `ist {hoch}` → `hoch`) — пустое поле, форма поля не должна
  выдавать, есть окончание или нет. Если ответ меняет основу (`hoch → hohes`,
  `dunkel → dunklen`) или артикль (`der → den`), остаётся ввод слова целиком.
  Флаг `full: true` на задании принудительно включает ввод слова целиком.
- У каждого задания поле `why` — короткое объяснение по-русски, показывается после ответа. Не «неверно»,
  а почему именно так: какой род, какой падеж, какой сигнал.
- День = 14–18 заданий, примерно 30–40 минут. Смешивать типы, не давать подряд пять одинаковых.
- Лексика берётся из соответствующего урока lehrerlenz, а не выдумывается с нуля.
- Порядок внутри дня: узнавание (`choice`) → подстановка (`fill`) → перевод с русского (`translate`).

## Где это живёт

Рабочая копия для телефона — артефакт claude.ai:
https://claude.ai/artifact/RTpbFXCnadZoeUwTKicZcu

Публикация: инструментом Artifact, тем же `url`, файлы передаются картой
`index.html` + `css/app.css` + `js/*.js` + `data/*.js` + `icon-180.png`.
Файлы берутся с диска как есть, содержимое уроков через контекст не гоняется.

Прогресс — sync engine на журнале операций (`js/sync.js`, глобал `window.Store`).

- Интерфейс читает только локальное состояние, сеть в пути ответа не участвует.
- Изменение состояния = мутация (`Store.mutate("vocabGrade", {...})`), прямых
  присваиваний в состояние в `js/app.js` быть не должно.
- Мутация ложится в журнал и применяется сразу; состояние = детерминированная
  свёртка снапшота и всех журналов. Время берётся из операции (`op.t`),
  не из часов — иначе свёртка на другом устройстве даст другие сроки.
- Порядок: часы Лампорта, ничья по идентификатору устройства.
- Каждый экземпляр страницы пишет только свой документ `oplogs/<writer>` и
  свой ключ localStorage. Одновременные ответы вкладок не заменяют друг друга.
  После офлайн-перезагрузки прежние локальные операции передаются в поле
  `relayed` своего документа с исходными автором и номером, без записи в чужой
  документ. Свертка устраняет дубликаты по автору и номеру операции.
- Изредка состояние сворачивается в `sync/snapshot` с курсором, журналы
  подрезаются по нему с запасом.

Новый вид изменения состояния = новый тип операции в редьюсере `apply()`
плюс вызов `Store.mutate` в приложении. Меняешь смысл существующих операций —
поднимай `SCHEMA` и пиши перенос, старые данные должны подниматься.

Ключи в localStorage: `de-b1-progress-v1` (материализованное состояние),
`de-b1-oplog-v2:<writer>` (журналы экземпляров страницы), `de-b1-snapshot-v1`,
`de-b1-device-v1`. Прежний `de-b1-oplog-v1` читается без перезаписи.
Принятые журналы сохраняются в `de-b1-foreign-v1` для офлайн-перезапуска.
Сессии `de-b1-session-v1` и `de-b1-review-v1`, черновики `de-b1-days-v2` локальны,
но входят в резервную копию версии 2. Сессия ошибок хранит конкретный вариант,
ввод и результат. `reviewAnswer` атомарно считает попытку и обновляет очередь;
повторная запись той же попытки ничего не меняет. Другой пример разрешен только
при совпадении `skill`; без разметки сохраняется исходное упражнение.
Старый черновик `de-b1-day-v1` переносится при открытии соответствующего дня.
Прогресс схемы 6 переносит схемы 2-5. Новое расписание использует `vocabReview`;
старые `vocabGrade` должны сохранять прежнюю семантику при свертке.

Перед каждой публикацией печатать версию: `./tools/stamp.sh <номер версии артефакта>`.
Она выводится в правом нижнем углу над панелью вкладок — по ней видно,
доехала ли свежая публикация до телефона. Номер берётся из ответа инструмента Artifact.

Локальная проверка: `python3 -m http.server` отдаёт файлы с кэшем, браузер
показывает старый JS. Поднимать `python3 tools/serve.py` — тот же сервер,
но с заголовком `Cache-Control: no-store`.
Из облачной сессии локального сервера нет вовсе — проверять чтением кода
или публикацией артефакта.

Тесты без зависимостей, запускаются node:

- `node tools/test-sync.js` — свёртка журнала, подъём состояния с диска
  и из облака, флаг готовности. Браузер подделывает `tools/env.js`.
- `node --test tools/test-regressions.js` - потери прогресса, компакция, миграция,
  поврежденное хранилище, импорт, квота, черновики, немецкие буквы и расписание.
- `node tools/test-lessons.js` — данные уроков: типы заданий, совпадение
  числа пропусков с числом ответов, ссылки на блоки теории, наличие `why`.

Состояние на телефоне живёт не вечно: хранилище артефакта переживает не каждое
открытие, и тогда прогресс приходит только из облака. Пока он не пришёл,
`Store.ready()` возвращает false, а интерфейс рисует прочерки — нули вместо
прогресса читаются как потеря данных. Новые экраны со статистикой обязаны
это учитывать.

Прогресс с телефона читается прямо из БД артефакта инструментом ArtifactData:
`list oplogs` (документ на устройство) и `get sync/snapshot`. Отдельно
выгружать ничего не нужно.

## Карточки слов

- При выборе близких по смыслу вариантов основной - естественный для повседневного
  общения; книжный или официальный указывать второстепенно в `reg` на обороте.
  Перевод и пример должны соответствовать основному варианту. Не подменять смысл
  ради упрощения: близкие выражения не всегда взаимозаменяемы.
- В общем словаре `f` задаёт приблизительную учебную очередь, а не корпусную
  частотность. После замены слова пересматривать группу. Поле `id`, если задано,
  сохраняет старую идентичность карточки для прогресса и незавершённых сессий;
  использовать `id || de` и в обычном выборе, и в калибровке.
- Жесты: вправо — «знаю», влево — «не помню», вверх — «уже знаю» (слово
  закрывается целиком, оба направления), тап — переворот.
- Все числа расписания находятся в `js/srs-config.js`. Новые ответы используют
  короткие шаги: ошибка через минуту, первый успех через десять минут,
  следующий успех после назначенного срока через сутки. Затем интервал растет
  с учетом легкости и детерминированного разброса. Срыв возвращает обучение.
  Бонуса за скорость и автоматического закрытия нового слова больше нет.
  Старые параметры нужны для воспроизводимой свертки исторического журнала.
- Дневной лимит новых слов - десять, при большом долге повторения новые
  блокируются. Новая лексика будущих уроков не вводится раньше текущего.
- Промах уже назначает срок; ранние повторные клики не увеличивают интервал.
- Калибровка (`#/vocab/calibrate`): по четыре слова с каждой ступени
  словаря, знакомое закрывается по самооценке, по долям выбирается группа.
  Это не измерение CEFR; статус в интерфейсе называется «закрыто».
- Обратное направление слова (русское → немецкое) открывается только через
  сутки после ответа на прямой стороне, иначе те же слова возвращаются
  «новыми» в следующей же сессии.
- Сессии: обычная — 10 карточек, повторение — 20. Промах возвращается
  в конец круга, а не через несколько карточек.

## Платформа

Приложение только мобильное — основное устройство iPhone. Вёрстка и жесты рассчитываются
под телефон, проверяются на ширине 390–420 px. Десктопный функционал не добавлять:
никаких подсказок про клавиатуру, горячих клавиш как основного способа управления,
ховер-состояний как единственного сигнала. Всё, что делает пользователь, должно
делаться пальцем. Полос прокрутки быть не должно — ни вертикальной, ни горизонтальной.

## Стиль кода

ES5-совместимый синтаксис в `js/` (файлы грузятся как обычные скрипты, без модулей и сборки).
Данные уроков — обычные объектные литералы, HTML теории в шаблонных строках.

## Результаты занятий и резервные копии

Черновиками управляет `js/practice.js`, валидацией и календарем - `js/progress-data.js`.
У каждого дня свой черновик с вводом, результатами и подсказками. Первая попытка
считается один раз по идентификатору; последние 100 завершенных попыток хранятся
в прогрессе. Пустой ответ не проверяется; нулевое окончание выбирается кнопкой ∅.
Несовпадающий открытый перевод требует проверки смысла и не считается доказанной ошибкой.

Экспорт и импорт находятся в «Ещё». Проверяй все данные до мутации. Поврежденные
исходники нельзя молча перезаписывать, а ошибку квоты нужно показать с возможностью
экспорта и повтора сохранения. Новые резервные копии переносят прогресс и черновики
дней; сессия слов остается локальной. Не обещай общую готовность к B1 по проценту
готовых дней. Подробный аудит и ограничения: `docs/main-audit.md`.
