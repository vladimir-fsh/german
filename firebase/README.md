# Firebase

Проект: `deutsch-a2-b1`, Firestore Standard, `europe-west3` (Frankfurt), тариф Spark.
Вход: Google; разрешённый домен приложения: `vladimir-fsh.github.io`.

Правила в `firestore.rules` опубликованы через Firebase CLI. Изменение правил
в Git само по себе их не публикует. При последующих изменениях проверить правила
и выполнить deploy только `firestore:rules`.

Web-параметры в `js/cloud-config.js` публичны. Firestore проверяет вошедшего
пользователя и разрешает доступ только к его `/users/{uid}/…`.

Первое подключение: в приложении на устройстве с основным прогрессом открыть
«Ещё → Облако и вход», войти через Google. Синхронизация подключается автоматически.
На другом устройстве войти в тот же аккаунт; прогресс загрузится автоматически.
После подключения ответы и изменения личного курса отправляются автоматически.
Без сети они остаются в местном журнале.

Если на втором устройстве уже другой исходный прогресс, синхронизация остановится.
Экспортировать обе версии перед выбором основного источника. Их стартовые снимки
не складываются автоматически, чтобы не удвоить ответы или затереть расписание.

Черновики и незавершённые сессии копируются отдельно от общего прогресса.
Для продолжения выбрать копию в «Занятия с других устройств»; эта команда заменяет
только местные черновики и сессии, завершённые ответы остаются общими.

Google-вход следует проверять на опубликованном HTTPS-адресе. LAN-адрес локального
предпросмотра не входит в разрешённые OAuth-домены. Popup выбран для GitHub Pages,
чтобы не зависеть от cross-origin storage при redirect-входе на стороннем хостинге.

Автоматические проверки: `node --test tools/test-cloud.js`.
Они используют подставной Firebase, без сетевых запросов и личных ключей.

## Чат без отдельного сервера

Пользователь выбрал прямые запросы к OpenAI из браузера. Firebase остаётся на Spark;
Cloud Functions, Secret Manager, сервисный аккаунт и Blaze не требуются.

Личный ключ хранится отдельно от прогресса: `users/{uid}/germanSecrets/openai`,
поля `key` и `updatedAt`. Правила разрешают чтение, удаление и запись только
владельцу аккаунта, проверяют формат ключа и серверную временную метку. Список
ключей и доступ другим пользователям закрыты. Остальные правила прогресса не меняются.

Ключ загружается Firestore SDK после Google-входа и используется в заголовке
`Authorization` прямого запроса к `https://api.openai.com/v1/responses`.
Он доступен авторизованному браузеру. Приложение не сохраняет его в localStorage,
журнале, резервной копии или исходниках; дисковая персистентность SDK не включена.
Сохранённый ключ в поле не выводится. Данные беседы не записываются в Firebase.

Правила нужно опубликовать перед использованием новой версии клиента:

```sh
npx firebase-tools deploy --only firestore:rules --project deutsch-a2-b1
```

Этот deploy не подключает оплату и не меняет документы Firestore. Он сохраняет
существующие ограничения прогресса и добавляет отдельный доступ к личному ключу.
Push в GitHub публикует интерфейс через Pages, правила Firestore он не публикует.

После обновления сайта войти через Google, открыть «Чат → Добавить API-ключ»,
ввести ключ и сохранить. Проверить объяснение, уточняющий вопрос и другое устройство.
При ответе OpenAI 401 приложение снова предлагает добавить действующий ключ.
Повторное открытие чата читает актуальную настройку, поэтому замена с другого
устройства доступна без повторного ввода. Ключ вводится только в приложении;
не отправлять его в чат Codex и не вставлять в терминальные команды.

Проверки без личных ключей: `node --test tools/test-cloud.js tools/test-tutor.js tools/test-tutor-session.js tools/test-tutor-request.js`.
